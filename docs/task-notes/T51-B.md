# T51-B — Fork-ready links, README and contributor guide

**Status:** complete with caveats. Everything in the task is built and checked on macOS. The caveats: the README and CONTRIBUTING wording is new prose that the user has not yet read, and the README does not link to massimg.com because the site is not deployed yet (T52).

## What was built

Cognirush's own contact points now live in one `operator` block in `src/config/site.ts`. The footer and credits page import it, and the four content pages use `{{token}}` placeholders that are filled in when a page is loaded. `README.md` exists for the first time, and `CONTRIBUTING.md` gained sections on where help is welcome, the simple-mental-model principle, AI use, why a green run is not the whole proof, and forking.

- `src/app/content/content.ts`: `substituteOperatorTokens`, applied in `loadRawContent`, so the rendered page, the FAQ JSON-LD and `useRouteSeo` all see resolved text. An unknown token throws.

- `src/app/content/content.spec.ts`, `extractFaqEntries.spec.ts`, `SiteFooter.spec.ts`, `CreditsPage.spec.ts`: token tests; the footer and credits specs now assert the config value rather than a copy of the URL.
- `README.md` (new), `CONTRIBUTING.md`, `.github/pull_request_template.md` (AI use and hand-check sections), `AGENTS.md` (layout lines; content authors must use tokens), `docs/tasks.md` (this task's entry).

## Decisions made

1. **Plain constants, not environment variables.** Vite bakes a module into the build already, and these values are not secrets or per-environment. Alternative rejected: a runtime `config.json`, which the prerender, sitemap and JSON-LD could not see.
2. **The task is T51-B, not T51-A.** T51-A already exists (placeholder audit) and is referenced from T46, T51.md and the backlog.
3. **Terms sections 10 and 11 stay literal.** They name Cognirush as the original author and state the redistribution conditions `NOTICE.txt` requires; substituting them would make a fork's Terms claim our IP and our restrictions as its own. The legal entity name is a token elsewhere (user's choice).
4. **No massimg.com build script.** `VITE_SITE_BASE_URL` and `VITE_CF_BEACON_TOKEN` carry everything that differs; T51-A and T52 set them.
5. **The README's desktop link and the CONTRIBUTING forking list are prose, not tokens.** Markdown outside `content/` is not built.
6. **README compares web and desktop in a table and links the credits page** (`https://massimg.com/credits`, which is not live until T52) and `3rd_party_licenses/`. The user supplied the desktop-only feature list and the three web-only features (size target, rotate and crop, Share).
7. **README browser notes restate the FAQ's section 8 and BL-010/BL-019 and add nothing new.** Where the FAQ says "untested" (iPhone, iPad, GNOME Web), so does the README.

## Surprises

- **`routes.spec.ts` "the footer and header reach every public page without a reload" is flaky on Firefox, on `main` too.** 7 of 20 runs failed with the change stashed (`NS_BINDING_ABORTED` from a worker, raised by Firefox's automation layer) and 0 of 20 with it. One full `test:e2e:site` run with the change also hit it once. It is not caused by this task; it is a different flake from the ones in T51.md.
- The prerendered HTML is unchanged. Compared against a build of the stashed tree, the six pages, `sitemap.xml`, `robots.txt` and `llms.txt` are identical once content-hashed asset names and Vue's `data-v-*` scope ids (which change whenever a component's script does) are normalized.

- **The Desktop page has the same web-versus-desktop table as the README** (`content/en/desktop.md`, with table styles added to `ContentPage.vue`, which had none). It was checked in all three engines for sideways page scroll at 320 to 1440 px and by axe, using a temporary spec that was removed afterward. Axe flagged a contrast failure on the "Download the desktop app" link: red `#cf0000` on black, 3.65:1 against the 4.5:1 minimum. That link style is `.content-page a` and applies to every content page's links, so it is not caused by the table; it is not fixed here and no existing spec covers content pages for contrast.
