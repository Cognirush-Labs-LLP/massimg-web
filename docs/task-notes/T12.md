# T12 — Output naming

**Status:** complete

## What was built

Pure output naming now preserves original extension spelling under unchanged-format routing, applies
canonical extensions for selected formats and resolved fallbacks, and retains folder-relative paths.
Batch naming resolves later collisions with numeric suffixes independently within each directory.

## Files touched

- `src/domain/naming.ts` — output-extension selection, relative-path preservation, and per-directory
  collision resolution.
- `src/domain/naming.spec.ts` — mixed-case, canonical-extension, fallback, collision, and folder-tree
  coverage.
- `docs/task-notes/T12.md` — this handover note.

## Decisions made

- `NamingInput` takes the T09 source metadata, T11's batch `FormatSetting`, and the successful resolved
  `EncodableFormat`. Rejected format resolutions cannot be named. This keeps naming pure while letting it
  distinguish a genuinely unchanged format from a JPEG fallback or animated WebP substitution.
- Original extension spelling is retained only when the setting is `dont-change` and the resolved format
  equals the detected source format. A fallback or substitution under `dont-change` uses the canonical
  resolved extension, as required by R-F2 and R-F6. An explicit format selection uses that format's
  canonical extension, including when it names the same detected format; R-X43 scopes exact extension
  retention specifically to `Don't change`, while R-F3 says format selection drives the output extension.
- The function returns output paths in input order, so each result stays aligned with its input and
  “later entry” collision behavior is deterministic. It prefers `relativePath` for folder inputs and falls
  back to `name` for ordinary file input.
- The last dot in the filename separates the base from the extension, preserving earlier dots. Collision
  suffixes are inserted between that base and the selected extension, and an occupied generated suffix is
  skipped rather than producing a second collision.
