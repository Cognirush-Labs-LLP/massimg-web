# T44 — Public content pages

**Status:** complete

## What was built

A markdown content pipeline (`src/app/content/`) that loads `content/<locale>/<page>.md` as
raw text at build time, falls back to the default locale when a locale-specific file is
missing (R-S5), and renders it to HTML via `markdown-it` for a shared `ContentPage.vue` to
display. The four pages it serves: FAQ (`content/en/faq.md`, untouched — already real,
already correct per T42's own note to re-read it), Privacy and Terms (new, explicitly-labelled
placeholder content per Technical Design §12.4's own framing that the real legal text is out
of scope here), and Desktop (new, real content: a short page about the separate desktop app
with a download link to `https://mic.cognirush.com/download/`). Built in the same pass as T43
— see `T43.md` for the shell/routing half this plugs into.

## Files touched

- `src/app/content/content.ts`, `content.spec.ts` — new. `loadRawContent(locale, page)`, via
  `import.meta.glob('/content/*/*.md', { eager: true, query: '?raw', import: 'default' })` —
  works identically in dev, client build and the Node SSG pass, no runtime fetch.
- `src/app/content/renderMarkdown.ts`, `renderMarkdown.spec.ts` — new. Thin `markdown-it`
  wrapper (`html: false`), pure function, unit-tested without mounting a component.
- `src/app/content/ContentPage.vue` — new. Takes a `page` prop, loads + renders that page's
  markdown via `v-html`, with hand-scoped (not Vue `scoped`) typographic CSS — see Decisions
  made.
- `src/app/FaqPage.vue`, `PrivacyPage.vue`, `TermsPage.vue`, `DesktopPage.vue` — new. Each a
  one-line wrapper (`<ContentPage page="…" />`); these are what T43's router points its new
  routes at.
- `content/en/privacy.md`, `content/en/terms.md`, `content/en/desktop.md` — new. `faq.md` not
  touched.
- `package.json`/`pnpm-lock.yaml` — added `markdown-it` (dependency) and `@types/markdown-it`
  (devDependency); no markdown parser existed anywhere in the repo before this.

## Decisions made

- **`markdown-it` over a hand-rolled parser.** The FAQ's existing content already uses
  headings, bold, links and lists; a hand-rolled parser risked subtly mis-rendering it. No
  markdown library existed to reuse, and `markdown-it` has no runtime DOM dependency, so it
  works identically in the Node SSG pass.
- **`ContentPage.vue`'s `<style>` block is not Vue-`scoped`.** `v-html`-injected content never
  carries the component's scope attribute, so `:deep()` was the only way to target it under
  `scoped` — and stylelint's `selector-pseudo-class-no-unknown` (no Vue-aware config exists in
  this repo) rejected it outright. Rather than add a stylelint override for a pattern used
  nowhere else in the codebase, the block is a plain global stylesheet hand-scoped under the
  single `.content-page` class, which needs no config change and is the conventional way to
  style injected HTML.
- **Locale is hardcoded to `defaultLocale` in `ContentPage.vue`**, matching `src/i18n/t.ts`'s
  own established "no real switcher yet" state. Wiring the actual active locale through is
  T48's job, once a second locale exists to make it observable.
- **Privacy/Terms placeholders are deliberately inert Lorem-ipsum-style text under clearly
  labelled "Placeholder content — not final legal text" headings** — not styled to look
  authoritative, per the user's explicit "not make it look real" instruction and Technical
  Design §12.4's own framing that the real legal text is future work by someone else.
- **Desktop page's download link goes to the external URL directly** (`content/en/desktop.md`
  is plain markdown: `[Download the desktop app](https://mic.cognirush.com/download/)`), kept
  as ordinary content rather than any special-cased routing/redirect — Technical Design §12.4
  treats Desktop as a markdown content page like the other three, not a redirect mechanism.

## Surprises

- **No markdown parser, no locale-fallback helper, and no `public/` directory existed yet** —
  confirmed by search before writing anything, so none of this pipeline was duplicating
  existing work.
- See `T43.md`'s Surprises for the two real e2e regressions this combined T43+T44 pass caused
  and fixed (duplicate header text; a pixel-calibrated Edit-mode drag test needing viewport
  compensation) — neither originated in this task's own files, but both were only visible once
  T44's routes existed to navigate to during verification.

## What the next task should know

- **T45 (SEO surface)** will want per-route metadata for these four pages; nothing here
  computes a page title or description beyond the shared `index.html` default — see T43.md.
- **T48 (Language completeness)** is explicitly where `ContentPage.vue`'s hardcoded
  `defaultLocale` gets replaced with the real active locale, once `content/<other-locale>/` and
  `src/i18n/<other-locale>/` directories start existing side by side. `loadRawContent`'s
  fallback path is written and unit-tested now but currently unreachable in practice (only
  `en` exists) — T48 is what first exercises it for real.
- **The real Privacy/Terms legal text is still nobody's engineering task** — per Technical
  Design §12.4, that's explicitly out of scope for this list and not something a future
  numbered task is expected to pick up on its own; someone needs to supply real copy before
  release.

## Requirements covered

unit-tested in `content.spec.ts`). R-S2/R-S3 (shell/routes) are T43's, covered in that note.
