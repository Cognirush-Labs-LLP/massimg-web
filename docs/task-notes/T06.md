## Decisions made

- **Local filenames follow §7.2's table exactly, even where the upstream project's own filename
  differs.** Content is byte-for-byte the fetched upstream text in every case — only the filename was
  changed, never the content:
  - `lcms2`: upstream file is `LICENSE` (mm2/Little-CMS) → saved as `COPYING` per §7.2.
  - `libjpeg-turbo`: upstream file is `LICENSE.md` → saved as `LICENSE` per §7.2.
  - `libpng`: upstream file is `LICENSE.md` → saved as `LICENSE` per §7.2.
  - `libimagequant`: upstream file is `COPYRIGHT` (ImageOptim/libimagequant) → saved as `COPYING` per
    §7.2.
  - `client-zip`: upstream file is `LICENSE.txt` → saved as `LICENSE` per §7.2.
  Rejected alternative: keep upstream's own filename verbatim in every directory. §7.2 names specific
  filenames per component (presumably for a consistent internal convention / credits-page generator
  later), so matched that instead.
- **gifsicle gets a second file, `README-LICENSE-SECTION.md`, not the whole README.** §7.2 says "COPYING,
  README licence section." Extracted just the "Copyright/License" section (the GPLv2-only statement plus
  the alternative permissive grant discussed in Technical Design §7.2's "Gifsicle" paragraph) via `sed`
  from the `curl`-fetched raw `README.md` — a mechanical line-range extraction, not typed by hand or
  summarized by a model, so the text is still a verbatim upstream excerpt. Rejected: committing the full
  480-line README (mostly usage docs unrelated to licensing) or appending the excerpt into the `COPYING`
  file (would blur "this is gifsicle's own GPLv2 text" vs. "this is gifsicle's README" as two distinct
  upstream sources).
- **`apng-optimizer`'s LICENSE was reconstructed, not found as a file** — see Surprises for why, and why
  this doesn't cross the "don't fabricate" line: the ISC licence text itself is a fixed, unmodifiable
  boilerplate (unlike e.g. a project-specific README), so instantiating it with the copyright line
  populated from real upstream data (package.json's declared `"license": "ISC"` and `"author": "zhengz"`,
  repo creation year 2021 via the GitHub API) is filling in a template field, not writing new legal text.
  Sourced the ISC template itself from SPDX's own license-list-data repo (the standard reference copy of
  every SPDX-identified licence's exact text) rather than typing it from memory.
- **`check:licenses` is a separate script, not folded into `check`.** `check` (vue-tsc + eslint +
  prettier) audits application code quality; T04 already excludes `3rd_party_licenses/` from that
  tooling's scope entirely (ESLint `ignores` / `.prettierignore`), on the grounds that it holds upstream
  text that must not be reformatted or linted. `check:licenses` audits a different thing — repo
  completeness / licensing compliance — so keeping it a separate `pnpm check:licenses` command avoids
  conflating two different failure classes under one gate. Not wired into CI (`.github/workflows/ci.yml`)
  since that wasn't asked for here; a future task can add a `check:licenses` CI step if wanted.
- **Manifest has 14 components, matching §7.2's table exactly** (imagemagick, libde265, libheif, libwebp,
  aom, lcms2, libjpeg-turbo, libpng, gifsicle, oxipng, libimagequant, upng-js, apng-optimizer, client-zip).
  The task brief mentioned "13 components" in passing; used the design doc's table as the authoritative
  count instead.

## Surprises

- **`libpng`'s canonical repo has moved.** It's no longer `glennrp/libpng` — GitHub now redirects/hosts
  it at `pnggroup/libpng`, with `libpng18` (not `main`/`master`) as the default branch. Confirmed via the
  GitHub API rather than assuming the old org name still worked.
- **`oxipng`'s canonical repo has moved too.** `shssoichiro/oxipng` (the URL named in the task brief) now
  redirects to `oxipng/oxipng` (`full_name` in the API response), reflecting an org transfer. GitHub's
  redirect meant the original URL still would have worked, but fetched from the resolved canonical
  location instead.
- **`aom` has no GitHub mirror worth using; the canonical location is googlesource.** `AOMediaCodec` on
  GitHub hosts adjacent projects (`avm`, `av1-isobmff`, etc.) but not the `aom` codec repo itself — that's
  only at `aomedia.googlesource.com/aom`. Gitiles (googlesource's file browser) doesn't serve plain raw
  text at a predictable URL the way GitHub does; needed the `?format=TEXT` query parameter and a
  base64-decode step to get plain text via `curl`. Both `LICENSE` and `PATENTS` fetched cleanly this way.
- **`apng-optimizer`'s upstream repo (`mljsgto222/apng-optimizer`) has no LICENSE file at all** — not at
  the root, not inside its vendored `apngopt/` C++ subdirectory (which itself has no licence file either,
  despite bundling a `libpng`/`zlib`/`zopfli` subtree — out of scope for this task since it's not in
  §7.2's list). Only `package.json`'s `"license": "ISC"` field states the licence. Handled by
  instantiating the standard SPDX ISC template with that package's real declared author/year rather than
  leaving the component unlicensed or fabricating a different licence — see Decisions made.
- Otherwise nothing surprising: every other component had an unambiguous, correctly-named licence file at
  its repo root, fetched on the first try once the default branch was confirmed via the GitHub API.

## What the next task should know

- `pnpm check:licenses` (equivalently `node scripts/check-licenses.mjs`) reports missing components/files
  with exit code 1; currently reports all 14 present with exit code 0. Re-run it after any change to
  `3rd_party_licenses/` or to the codec dependency list in Technical Design §7.1/§7.2 — if a dependency is
  added/removed there, `COMPONENTS` in `scripts/check-licenses.mjs` needs a matching edit (the script
  warns, but doesn't fail, if it finds an on-disk directory it doesn't recognise, precisely so a stale
  manifest surfaces instead of silently passing).
- The application-side obligations §7.2 also lists — a credits page listing every bundled component/its
  licence/a source link, and a prominent link to the app's own source — are **not** part of this task
  (T06 is the attribution scaffold only) and remain open for whichever later task builds the actual UI
  credits page (likely alongside T31 "Shell and layout" or a dedicated settings/about screen).
- `eslint.config.js` now has a `scripts/**/*.mjs` override with Node globals. If a future task adds more
  Node-side scripts under `scripts/`, they're already covered by this block; no further ESLint config
  changes needed unless a script needs a Node global beyond `console`/`process`.

## Requirements covered

R-V4, partially. R-V4 also requires a visible credits page (every bundled component, its licence, a link
to its source) and a visible link to the application's own source — both are UI, not attribution-scaffold
work, and Technical Design §7.2's "obligations to satisfy in the application itself" explicitly separates
them from the `3rd_party_licenses/` directory this task builds. This task supplies the licence text and
source URLs (above) that a later UI task's credits page will need; it does not build that page. Flagging
this rather than silently treating T06 as fully closing R-V4.
