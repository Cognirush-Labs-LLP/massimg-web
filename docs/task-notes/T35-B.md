# T35-B — WebP for animated images

**Status:** complete

## What was built

A batch-wide `animatedAsWebp` setting (default on) and a "WebP for animated images" checkbox under the Format dropdown, shown whenever the chosen format is JPEG or AVIF. Off, `resolveFormat` resolves an animated source to a still job in the requested format with an `animation-flattened` caveat, and the existing still pipeline writes its first frame. On, behaviour is unchanged.

## Decisions made

- `animatedAsWebp` is a required field on `BatchSettings`, so a call site that forgets it fails type-checking instead of silently taking the first-frame path. `describeReportSettings` takes `Omit<BatchSettings, 'animatedAsWebp'>` because the report states no such line; the per-image caveat is the report mechanism.
- Native checkbox, not `ToggleSwitch` (a two-option switch).
- Hint wording avoids a plural-sensitive noun ("Animated images in this batch: {count}") because the catalogue has no plural handling.
- The setting is not persisted, like every other batch setting.
- Edit stays unavailable for animated sources (R-C16), also when they are written as a first frame.
- Warning colour is an amber text token and border; the UI is dark-only, so no light-theme variant.

## Surprises

none. `decodeFrame` returns the full first frame for GIF, WebP and APNG on all three engines (A3 extended), so the planned fallback to `decodeAnimation` was not needed.

## What the next task should know

The Preview recovery path already skips animated images (`image.isAnimated`); a first-frame image is still `isAnimated` on the record, so size-target recovery does not run for it either. Thumbnail and the Original tab still play the animation (R-P8), which is correct: the Compressed tab shows the single frame.
