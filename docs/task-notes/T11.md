# T11 — Format routing

**Status:** complete

## What was built

Pure per-image format routing now resolves the batch format setting, including per-image "Don't
change", JPEG fallback for decode-only inputs, animation-preserving WebP substitution with a caveat,
and animated AVIF rejection. Format capability helpers expose alpha and animation support, and a
table-driven unit test covers all 132 combinations of source format, animated state, and batch format
setting.

## Files touched

- `src/domain/format.ts` — format-setting and resolution types, the pure per-image resolver, animated
  AVIF rejection, and alpha/animation capability helpers.
- `src/domain/format.spec.ts` — exhaustive routing matrix and capability tables.
- `docs/task-notes/T11.md` — this handover note.

## Decisions made

- `FormatSetting` is `EncodableFormat | 'dont-change'`. The sentinel stays distinct from `Format` and
  `EncodableFormat`, following T09's handover, so callers can retain the batch-level choice while the
  resolver produces an actual per-image output format.
- `resolveFormat` returns a discriminated `FormatResolution` rather than throwing for animated AVIF.
  The rejected branch carries the stable reason `animated-avif-input`, allowing selection handling to
  name the reason required by R-F8 without treating it as a processing `FailureReason`; T09 explicitly
  reserved that type for failures after an image has entered the batch.
- Resolution order is animated-AVIF rejection, "Don't change" output selection (including JPEG
  fallback), then animated substitution when the resulting output is still-only. This means a
  hypothetically animated decode-only input under "Don't change" becomes animated WebP with the same
  substitution caveat rather than being silently flattened to JPEG. That follows T11's general
  no-flattening rule and Functional Design P1; currently documented animated inputs are PNG, WebP, GIF,
  and rejected AVIF.
- Alpha capability accepts a resolved `EncodableFormat`, rather than a batch setting, because R-C13
  and R-C14 depend on the effective per-image output. JPEG is the only encodable format without alpha.

## What the next task should know

- Import `FormatSetting`, `FormatResolution`, `resolveFormat`, `supportsAlpha`, and
  `supportsAnimation` from `@/domain/format`.
- A resolved result provides the exact `EncodableFormat`, output `isAnimated` state, and caveat list.
  An animated source routed away from JPEG or AVIF has one `{ kind: 'animation-substituted' }` caveat.
- Animated AVIF returns the rejected branch for every batch setting and must remain excluded at
  selection time; callers should not build a job from that branch.
- No extension or filename policy was added. T12 should derive naming from a successful resolved
  format while preserving original extension spelling under "Don't change" where its requirements
  call for it.
