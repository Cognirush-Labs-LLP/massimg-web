# T14 — Settings resolution

**Status:** complete

## What was built

`domain/job.ts` now resolves batch quality, dimension and format controls into per-image
`ResolvedSettings`. Resolution composes with T11 format routing, applies T13 crop precedence, maps PNG
quality and all lossless thresholds, and selects the alpha policy and opaque fill colour for the
effective output format.

## Files touched

- `src/domain/job.ts` — batch-setting input types and the pure per-image settings resolver.
- `src/domain/job.spec.ts` — table-driven quality, dimension, format and alpha-resolution tests.
- `docs/task-notes/T14.md` — this handover note.

## Decisions made

- A crop override resolves the dimension to `{ kind: 'original' }`. At the resize stage this means
  “do not resize the already-cropped raster”, while leaving all four batch dimension variants available
  as resolver inputs.
- JPEG always resolves to a flatten policy, even when the source is known to be opaque. This is the
  encoder policy needed to guarantee an alpha-free output; whether pixels were actually flattened, and
  therefore whether R-C17's caveat is emitted, remains an observed pipeline result.
- A JPEG crop uses the most recent crop operation's RGB background with alpha resolved to `1`; without
  a crop, it uses opaque white. The stored `EditRecord` is not mutated, so switching back to an
  alpha-capable format restores its original alpha as required by R-C15. The current interface writes at
  most one crop, while choosing the last crop also matches ordered operation semantics if that expands.
- GIF quality above 95 resolves with `lossless: true`. For GIF this directs the later encoder to omit
  `--lossy`, matching Technical Design §7.4's “no `--lossy`” branch rather than claiming a separate GIF
  encoder mode.
- Successful settings resolution carries forward T11's format caveats, while animated AVIF rejection is
  passed through unchanged. This prevents the composed resolver from losing animation-substitution
  disclosure before a job is built.

## What the next task should know

- Import `BatchSettings`, `QualitySetting`, `SettingsImage`, `SettingsResolution` and `resolveSettings`
  from `@/domain/job`.
- PNG quality in resolved settings is the mapped encoder value, not the raw slider value. At slider 85
  it is `{ value: 95, lossless: true }`; slider 86 remains mapped (`95.333…`) even though the lossless
  path is selected.
- A size target remains `{ kind: 'size', targetBytes }` for every effective format. Pass-through for an
  already-small input, binary-search outcomes and format availability belong to the later size-target
  pipeline and interface tasks.
- `SettingsResolution.caveats` currently contains format-routing caveats. The transparency-flattened
  caveat must only be added after processing establishes that transparent pixels were actually flattened;
  `settings.alpha` supplies the policy and fill needed to do that.
