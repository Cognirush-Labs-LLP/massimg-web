# T47-B — Dimension setting help

**Status:** complete

## What was built

A "?" help affordance beside the Fit within long edge, Fixed width, and Fixed height rows in the
Dimension accordion, each opening a small, centred, focus-trapped dialog (new `HelpDialog.vue`)
with a short, plain explanation of the rule. The enlarge/shrink-only fact (R-N2) is a separate,
visually de-emphasised note fragment below the body rather than folded into it, and Fit within
long edge additionally shows a small landscape/portrait diagram marking which side is its "long
edge" — both refinements made after an initial pass used full, equally-weighted sentences for
everything and no diagram.

  title, body, an optional `note` (quieter typography) and an optional `#diagram` slot, one Close

## Decisions made

- **Built a new component (`HelpDialog.vue`) rather than extending `ConfirmDialog.vue`.**
  `ConfirmDialog.vue` is permanently active (`active: ref(true)`), has a no-op
  `returnFocusTo: ref(null)`, and its scrim deliberately has no click handler — all three the
  opposite of what this dialog needs (togglable, a real return-focus target, closes on scrim
  click). Branching those three behaviours into one component would have complicated the
  irreversible-decision case it already serves. `docs/tasks.md`'s "reusing ... the same dialog
  shell `ConfirmDialog.vue` already established" reads as a pattern reference (centred box, scrim,
  `role="dialog"`, `useFocusTrap`), not a literal-reuse instruction — borrowed the CSS and markup
  shape, not the component.
- **`HelpDialog` stays mounted at all times; `modelValue` is the real open/close toggle** — like
  `Drawer.vue`, not like `ConfirmDialog.vue` (which is mounted/unmounted by its parent, with
  `active` permanently `true`). This one mattered functionally, not just stylistically: the first
  implementation used `v-if="helpRow"` on `<HelpDialog>` itself with a hardcoded
  `:model-value="true"`, mirroring `ConfirmDialog`'s externally-mounted pattern. That broke
  return-focus-on-close, because `useFocusTrap` only calls `returnFocusTo.value?.focus()` on an
  `active` **true→false transition** inside its own watcher — closing by unmounting the component
  outright never produces that transition, it just tears down the listener. A test
  (`SidePanelDimension.spec.ts`, "Close returns focus to the help button") caught this before it
  shipped; fixed by keeping `HelpDialog` always mounted and driving `:model-value="helpOpenRow !==
  null"` as a genuine toggle.
- **`HelpDialog` uses `ConfirmDialog`'s z-index tier (scrim 28 / dialog 30), not `Drawer`'s (8 /
  10)** — the "?" button lives inside `SidePanelDimension.vue`, which renders inside `Drawer.vue`
  on mobile, so the help dialog must be able to sit above the open drawer.
- **One shared `HelpDialog` instance**, content swapped via a `helpOpenRow` ref and a `helpRow`
  computed lookup into `ROWS`, rather than three separate dialog instances.
- **Dialog title reuses each row's own existing `labelKey`** rather than a new, duplicate title
  string per row.
- **Literal "?" glyph**, matching `GalleryTile.vue`'s "×" remove-button precedent — no icon
  library exists in this codebase, and inventing an SVG for a single character seemed unnecessary.
- **`@click.stop` on the help button** even though reading the real template confirmed the
  `<label>` has no `@click`/`@change` handler of its own that could be triggered by bubbling (and
  a native label→radio click-forward is independently suppressed for a `<button>` descendant,
  which defines its own activation behaviour) — cheap, explicit insurance rather than relying on
  unwritten browser behaviour, and a test (`does not select the row when its help button is
  clicked`) verifies the actual outcome either way.
- **`shell.helpDialog.closeLabel`** lives in the generic `shell.*` namespace (next to
  `shell.leaveConfirm.*`), not `panel.dimension.*`, since `HelpDialog.vue` is written to be
  reusable by any future "?" affordance, not just this one.
- **The enlarge/shrink-only fact got its own prop (`note`) and its own, quieter typography**
  (`.help-note`: smaller, `--color-text-muted-quiet`), separate from the main `body` paragraph,
  after feedback that folding it into one sentence over-emphasised a secondary caveat. `note` is a
  fragment by design ("Shrinks only — never enlarges.", "May enlarge small images."), not required
  to be a grammatically complete sentence, since it reads as a label-like aside, not prose.
- **The Fit within long edge diagram is `aria-hidden`**, purely illustrative: two outlined
  rectangles (landscape, portrait), each with their longer side marked in `--color-primary` —
  never `--color-tint`, which functional-design.md §14.1 reserves for action/state, not
  decoration. Not added to Fixed width/Fixed height: both have one unambiguous axis already named
  in the row label, so there is nothing for a diagram to disambiguate.
- **`HelpDialog`'s diagram slot content is defined in `SidePanelDimension.vue`, not inside
  `HelpDialog.vue` itself** — confirmed that Vue's `scoped` CSS applies the *slot-defining*
  component's scope id to slotted content, not the child's, so `.long-edge-diagram`'s styles
  living in `SidePanelDimension.vue`'s `<style scoped>` block correctly reach the SVG even though
  it renders inside `HelpDialog`'s template.

## Surprises

The return-focus bug above (mount/unmount used as the open/close signal, defeating
`useFocusTrap`'s transition-based return-focus logic) — worth remembering for any future consumer
of `useFocusTrap`: the component must stay mounted across its own open/close cycle for
`returnFocusTo` to work, matching `Drawer.vue`'s pattern, not `ConfirmDialog.vue`'s.

## What the next task should know

`HelpDialog.vue` is intentionally generic (`modelValue`/`returnFocusTo`/`title`/`body`) — a future
"?" affordance elsewhere in the interface should reuse it directly rather than building another
near-duplicate, the same way `ConfirmDialog.vue` already serves two different back-navigation
dialogs.

## Requirements covered

R-D5 (new). R-K10 (the new icon-only button has a catalogue-sourced `aria-label`, no duplicated
visible text). R-K1/R-K3-equivalent keyboard behaviour (focus-trapped, Escape closes, Tab cycles)
inherited for free from `useFocusTrap`, already covered by that composable's own test suite.
