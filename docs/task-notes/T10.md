# T10 — Size formatting

**Status:** complete

## What was built

The domain now exports separate report and interface size formatters. Both select human-readable
1024-byte units and render two decimal places, while report numbers use locale-independent
dot-decimal formatting and interface numbers use `Intl.NumberFormat` with the active or requested
locale.

Focused tests cover byte/unit boundaries, rounding, fixed precision, distinct formatter identities,
output under `en-US`, `de-DE`, and `hi-IN`, and prove that report formatting never invokes
`Intl.NumberFormat`.

## Files touched

- `src/domain/sizes.ts` — shared 1024-byte unit scaling plus separate report and UI numeric formatters.
- `src/domain/sizes.spec.ts` — unit, rounding, formatter-separation, and locale tests.
- `docs/task-notes/T10.md` — this handover note.

## Decisions made

- The formatters share only the non-locale-sensitive byte scaling helper. Numeric rendering remains in
  two separate exported functions: `formatReportSize` uses `Number.prototype.toFixed`, while
  `formatUiSize` creates an `Intl.NumberFormat`. This avoids duplicating unit selection without
  weakening R-L3's requirement that report and interface numbers never share a formatter.
- Sizes below one kilobyte use `B`; larger values progress through `KB`, `MB`, `GB`, and `TB`, with TB
  as the highest unit. The design specifies 1024-byte units but does not enumerate labels; this finite
  set covers all practical browser-managed file and batch sizes without adding units the product does
  not otherwise mention.
- Both formatters always show exactly two fraction digits, including whole-unit values such as
  `1.00 KB`. This is the direct reading of T10's “two decimals” and keeps report output structurally
  consistent.
- `formatUiSize` accepts an optional `Intl.LocalesArgument`. Omitting it uses the browser's active
  locale; passing it makes locale selection explicit for callers and deterministic in tests. The report
  formatter deliberately accepts no locale argument because report output cannot vary by locale.
- No runtime policy for negative, fractional, non-finite, or unsafe byte counts was added. The task and
  design specify formatting of byte counts but do not define validation or error behaviour; producers
  of byte counts remain responsible for supplying valid sizes.

## What the next task should know

- Import `formatReportSize` and `formatUiSize` from `@/domain/sizes`. Use the report formatter only for
  the report's human-readable values and preserve raw numeric byte counts separately for R-X33.
- Passing no locale to `formatUiSize` delegates locale selection to the runtime. Tests and any caller
  that needs deterministic output can pass a BCP 47 locale such as `de-DE`.
- T11 does not need either formatter; no format-routing work was started here.

## Requirements covered

R-X32 (1024-byte human-readable sizes rounded to two decimal places), R-L3 (separate locale-independent
report and locale-aware interface number formatters). R-X33's boundary is preserved: the formatter
does not replace or round source byte counts, so T15's report model can carry exact numeric totals
alongside the formatted summary values as required.
