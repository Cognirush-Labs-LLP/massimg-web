# T36-A — Hard size ceiling and recovery

**Status:** complete

## What was built

Size targeting is now a hard per-image ceiling. The size planner and worker protocol return a
discriminated fit/output or `size-target-unreachable` constraint result; a run result never carries
oversized output bytes, while Preview replaces its image frame with a dark warning card. Single-still
Preview now checks verified PNG→JPEG and smaller-dimension alternatives through its worker pool,
reveals actions progressively, adds one free next-lower standard-size choice after a dimension fit,
and applies nothing until the user clicks. Leaving Preview cancels queued recovery work and resumes
the warmed pool on return, while any one codec call already inside WASM finishes and is discarded.

The domain also has a bounded dimension-recovery planner, an internal exact dimension, a trailing
post-crop resize operation, structured skipped-run/report state, and a `SKIPPED` Gallery badge.
Processing, archive assembly, and download UI remain their existing future tasks (T38–T42); those
tasks now explicitly consume these contracts and accept only `output` results.

## Decisions made

- Recovery stays inside the existing Preview orchestrator rather than gaining a second UI store.
  Its state is scoped to the mounted Preview component, which makes image/settings/edit changes and
  unmount release it with the same lifecycle as the ordinary Preview result.
- An unreachable attempt is metadata-only across the worker boundary. The warning replaces the
  image frame, so transferring and retaining bytes that the UI deliberately cannot display would
  add memory cost without helping the user.
- A non-cropped image maps a verified exact size back to the user's current batch dimension mode;
  an image with any stored edit receives the trailing exact resize. This keeps rotation/crop
  composition stable and gives T37 one operation to preserve or remove.
- The verified dimension search probes and performs its final search at quality 30 or better, rather
  than selecting dimensions that fit only at the slider's quality-10 endpoint.
- The free lower-size action uses `[240, 360, 480, 640, 720, 800, 1024, 1080, 1280, 1440, 1600,
  1920, 2048, 2160, 2560, 2880, 3200, 3840, 4096]` and chooses the greatest controlled edge below
  the measured fit. It has no byte-size label because it is not probed; the fresh ordinary Preview
  encode after selection remains the hard-ceiling authority.
- The Dimension panel mirrors store changes back into its per-row text-field cache, so a recovery
  action displays the exact verified long edge rather than the row's earlier value.
- Preview unmount uses the pool's existing cancel/resume behavior rather than terminating workers.
  This clears queued work and bounds rapid navigation by active pool slots without reloading codecs.
- `ImageRecord` exposes both nullable reason fields for ergonomic store/component use, while the
  batch store's `clearRunStatuses`, `markFailed`, and `markSkipped` methods enforce their
  mutual-exclusion invariant atomically.
- D10 uses a recovery-only mode in the existing T30 harness. It retains the same subjects,
  browsers, formats and shipped stages but avoids rerunning T30's unrelated target sweeps.

## Surprises

- The full T30 harness became memory-heavy when recovery was appended after all five codecs and all
  original target sweeps in one page; Firefox destroyed several page contexts. The recovery-only
  mode ran all 75 format/subject/engine rows successfully and is the recorded D10 evidence.
- PNG recovery is materially expensive after raising the recovery floor to quality 30: the worst
  complete search was 20,494 ms on Firefox versus 1,432–7,548 ms for the other formats. This
  supports, rather than changes, the single-still-only product boundary.

## What the next task should know

- T37 must preserve a trailing resize on Cancel, remove it when changed crop geometry is applied,
  and clear it with Remove edit. `geometryEdit()` and `withTrailingResize()` are the shared helpers.
- T38 must use its own worker pool as T36 already required. A completed
  `size-target-unreachable` result maps to `run.recordResult(..., { kind: 'skipped', reason })` and
  `batch.markSkipped`; it is not a failure. Start with `run.startRun()`, which clears prior statuses.
- T40 and direct-download assembly must narrow to `result.kind === 'output'`. The protocol's worker
  response `{ kind: 'skipped' }` still means cancellation before execution and must not be mapped to
  the product's Skipped outcome.
- T41 should pass the structured `SizeTargetSkipReason` directly to the existing report model.
- Recovery candidate bytes are deliberately unavailable to later tasks. Clicking a suggestion only
  changes state; Preview and Processing re-read and re-encode from the source.
