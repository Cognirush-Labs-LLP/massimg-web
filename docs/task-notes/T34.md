# T34 — Gallery, list view

**Status:** complete

## What was built

A list view for the Gallery, alongside the existing grid (T33-B): a toolbar toggle
(`GalleryToolbar.vue`) that switches between them, automatic initial-mode selection by file
count and folder origin (R-G8), and a new list body (`GalleryList.vue` + `GalleryListRow.vue`)
that renders relative path/filename/`W×H · size`/badges per row, grouped by directory when the
batch came from a folder. List mode never touches the thumbnail service or decodes anything —
enforced structurally (no import of `thumbnail-service.ts` anywhere in the list body or its
rows), not by a runtime check.

## Decisions made

1. **"Selects the initial mode automatically" (R-G8) is evaluated only on the empty→populated
   transition**, not re-run on every subsequent `addImages`. A session that starts with 5 loose
   images (grid) and grows past the threshold via repeated small adds stays in grid unless the
   user toggles, or clears and re-adds. Rejected alternative: re-evaluating on every add, which
   would silently flip a user's view out from under them mid-session with no override in effect
   yet — worse than under-triggering once.
2. **A manual override persists across an intervening Clear.** `galleryViewOverridden` is a
   session-scoped flag untouched by `clearAll()`; only `setGalleryView` sets it, and nothing
   resets it. The functional design says the override "persists for the session," and a Clear
   is well within the same session.
3. **List rows show the relative directory prefix per row**, not only via the group header
   (ui-design.md §7's "Row anatomy" lists "Relative path (only present for folder-sourced
   images) + filename" as row content, separate from the "Grouping" section that adds headers
   on top). This means the directory string is visually repeated once as a header and again per
   row beneath it in the common case — read as intentional given the doc lists both
   independently, not as redundancy to eliminate.
4. **Grouping merges by directory-string identity, not contiguous run.** Two separate "Add
   folder" actions producing images under the same relative directory string land in one group.
   Folder traversal already makes same-directory files contiguous in the normal case; this only
   diverges from a naive "break on directory change" reading if the same directory name recurs
   across two separate folder picks into one batch — an edge case neither design document
   discusses.
5. **List view is not virtualized.** R-G10's virtualization requirement is explicitly scoped to
   grid mode; list rows are text-only with no decode cost. Flagged as a future measurement
   concern if very large batches (the folder-traversal cap is in the low thousands) prove slow
   to render, not treated as a gap here.
6. **Toggle accessibility**: two `aria-pressed` buttons inside a labelled `role="group"`, not a
   `role="radiogroup"`/`role="radio"` pair — avoids roving-tabindex machinery for a two-state
   toggle. No existing toggle-control precedent elsewhere in `src/ui/` to match against.
7. **Badges shown in list rows too**, same fixed order as grid (EDITED → ANIMATED → FAILED) —
   not a choice, ui-design.md §7 states this explicitly ("Same badge set and order as grid
   tiles").

## Surprises

`npm run build` (vue-tsc + vite-ssg) fails on a pre-existing, unrelated error: `imagequant`'s
WASM worker bundling hits "Top-level await is currently not supported with the 'iife' output
format" in `src/platform/thumbnails.ts`'s worker chunk. Confirmed present on `main` before any
of this task's changes (verified via `git stash -u` + `npm run build`) — not something this task
introduced or was in scope to fix. `npm test` and `npm run check` (vue-tsc, ESLint, stylelint,
Prettier) both pass cleanly; the dev server serves the tool route and every new/changed module
transforms without error. Whoever picks up a production-build task (T52, "Build and deploy")
should know this blocker exists.

Otherwise nothing surprising — T33-A/T33-B's handover notes correctly anticipated everything
this task needed (the `galleryView` store stub, the toolbar's placeholder comment, the shared
populated header, and `GalleryGrid`'s unmount-triggers-stop precedent all worked exactly as
described).

## What the next task should know

- `imageMeta.ts` is now the single source of truth for badge order and dimension-pending/error
  text; any future tile/row visual change (e.g. an edit-invalidation indicator) should land
  there once, not in both `GalleryTile.vue` and `GalleryListRow.vue` separately.
- Fixture callers beware: `imageRecordFixture` (`domain/types.fixtures.ts`) has a **non-null**
  `relativePath` by default (`'photos/portrait.PNG'`), so spreading it unmodified into
  `addImages` now auto-selects **list** mode per R-G8. Tests that want to exercise grid-mode
  behaviour must explicitly override `relativePath: null`. This tripped three pre-existing
  `Gallery.spec.ts` tests written before this task existed; they're fixed here, but any new test
  elsewhere that adds the raw fixture and expects grid mode will hit the same thing.
- `useUiStore().galleryViewOverridden` exists alongside `galleryView` — any future code that
  needs to know "did the user choose this deliberately" (e.g. an analytics event, T46) should
  read it rather than re-deriving the distinction.
