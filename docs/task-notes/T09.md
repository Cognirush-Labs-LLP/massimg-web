# T09 — Core types

**Status:** complete

## What was built

The domain now has shared TypeScript definitions for image metadata, ordered edits, jobs, resolved
settings, formats, failures, caveats, and image identity. Reusable fixtures cover every core shape and
every edit/caveat variant, with a focused unit test that proves the fixture module is usable and edit
operation order is retained.

## Files touched

- `src/domain/types.ts` — core domain types, discriminated unions, and supporting value shapes.
- `src/domain/types.fixtures.ts` — exported, typed fixtures for later domain tests.
- `src/domain/types.spec.ts` — fixture smoke tests and the ordered-edit assertion.
- `src/domain/.gitkeep` — removed now that the directory contains real files.
- `docs/task-notes/T09.md` — this handover note.

## Decisions made

- All core definitions live in `src/domain/types.ts` rather than being split among future modules such
  as `format.ts` and `job.ts`. Those later modules will own behaviour; this task supplies their shared
  data contracts without starting T10 or later logic.
- `ImageId` is an opaque branded string, which prevents an arbitrary string from being passed where an
  image identity is required while retaining cheap string keys for maps. No additional ID aliases were
  invented: `ImageId` is the only identifier type named or used by the current Technical Design.
- `Format` covers every supported source format in Functional Design §5.1, using lower-case canonical
  identifiers. `EncodableFormat` narrows it to the five output formats the build can write. Rejected a
  single output-only union because `ImageRecord.sourceFormat` must also represent decode-only input
  such as HEIC, TIFF, BMP, JPEG XL, and JPEG 2000.
- The support types needed by the required shapes (`NormalisedRect`, `Rgba`, `EncodableFormat`,
  `ResolvedQuality`, `ResolvedDimension`, and `AlphaHandling`) are exported too. The resolved-setting
  branches are discriminated so later resolution and pipeline code can narrow them without nullable
  companion fields. `ResolvedSettings.isAnimated` carries the per-image output mode needed by the job
  because the `Job` shape does not otherwise contain source metadata.
- `Job.source` is a `Uint8Array`, using Technical Design §4's explicitly allowed "raw bytes, posted to
  the worker" representation instead of `File`. This keeps the Phase 2 domain boundary free of browser
  APIs and provides directly transferable job input.
- `FailureReason` represents the three processing failures that can apply to an `ImageRecord` after it
  has entered the batch: decode, encode, and out-of-memory. Selection rejections and archive/storage
  failures have different lifecycles and are not image-record failures, so were not folded into this
  type.
- `Caveat` is a discriminated union for the fixed nine-item set in R-X46. Variants carry only the facts
  R-X46 says must be stated (fill colour, GPS presence, byte values, or target/achieved size). Rejected a
  free-form string because that would make the supposedly fixed set unenforceable and would mix domain
  facts with later report/i18n wording.
- Fixtures are in a normal importable module and use `satisfies` rather than broad type annotations.
  This keeps literal discriminants narrow and makes the fixtures reusable by T10+ tests while still
  making `vue-tsc` verify every required field. Both `EditOp` variants and all nine `Caveat` variants
  have fixtures because later tests will need to exercise their discriminants.

## What the next task should know

- Import shared domain types from `@/domain/types`; test fixtures are available from
  `@/domain/types.fixtures`.
- `Format` includes decode-only formats. Code that needs an output format should use
  `EncodableFormat`, and T11's batch-level "Don't change" selection should remain distinct from both
  rather than adding a pseudo-format to `Format`.
- Numeric ranges (normalised rectangle bounds, RGBA channels, quality, dimensions) are contracts for
  the functions that construct/resolve these objects; TypeScript's number type cannot encode them and
  this task adds no runtime behaviour.
