# T49 — Privacy, credits and source

**Status:** complete with caveats

The one caveat is scope, not correctness: the Share sentence for `content/en/privacy.md` is
drafted and awaiting the user's approval rather than committed, because it is legal copy. See
"What the next task should know".

## What was built

The privacy line R-V1 asked for: both sentences in the Gallery empty state (the claim plus the
R-V3 analytics disclosure), with the footer's existing **Privacy** link carrying the
reachable-once-images-are-loaded half. A `/credits` route listing every bundled third-party
component with its licence, SPDX identifier, upstream source and a link to its actual licence
text served from our own origin — generated from a new
`3rd_party_licenses/components.json` that `scripts/check-licenses.mjs` now reads too, so the
audited set and the credited set are the same set. And the two tests that turn R-V2 and R-V5 from
claims into checks: a full-run Playwright request log, and an explicit-activation assertion on
Share.

## Decisions made

1. **The manifest is flat, 16 entries over 14 directories.** Two directories hold a JS wrapper's
   own licence beside the upstream library's (`gifsicle-wasm-browser`, the jSquash oxipng
   wrapper), so each is credited separately. Rejected: one entry per directory with a compound
   licence string, which loses which text covers which component; and a nested `bundled`
   sub-array, which is more schema for the same information.
2. **No free-text `note` field in the manifest.** English prose there would be user-facing copy
   outside §11's catalogue and its CI check. gifsicle's alternative-grant nuance stays in the
   committed `README-LICENSE-SECTION.md`, which the page links.
3. **`licenseId: null` is a value, not a gap**, used for the five components where a single SPDX
   identifier would be a false claim (imagemagick, libde265, libheif, libjpeg-turbo,
   libimagequant). The page renders the human-readable name and omits the identifier.
4. **`dist/` copy is a post-build node script, not a Vite plugin.** `vite-ssg build` runs two
   Rollup passes, so a plugin needs a `build.ssr` guard, and anything it emits exists in `dist/`
   while Workbox computes its precache manifest. Running after the build makes precaching
   impossible rather than merely unconfigured. Rejected also: `public/` (a committed second copy,
   or a gitignored one that breaks `pnpm dev` on a clean checkout) and adding
   `vite-plugin-static-copy` (a new dependency, needing its own licence directory, to solve a
   licensing-page problem).
5. **Verbatim filenames, with the production MIME header handed to T52.** The alternative was
   appending `.txt` to the served copies, which needs no server configuration but makes the
   displayed filename stop matching the repository — and still needs the dev middleware anyway, so
   it buys less than it appears to.
6. **`check:licenses` is now a hard CI step, and its stray-directory warning is now an error.**
   T49's done-when is that the page covers every directory; a warning cannot enforce that. Kept
   out of the `check` npm script for T06's recorded reason (that script's tooling deliberately
   excludes this tree).
7. **The footer carries no privacy line — just the existing `Privacy` link.** A 30-character
   line was built there first (it replaced the `Privacy` label and linked to the same page), and
   was removed on the user's instruction after it proved to cost stage height: see Surprises.
   R-V1's "remains reachable once images are loaded" is satisfied by the link; the claim itself
   is stated in full in the empty state, which is where R-V1 puts it.
8. **The analytics disclosure lives in the empty state.** R-V3 revises *the privacy line*, and
   the line is in the empty state.
9. **No header-nav entry for Credits** — footer only, the same class of link as Privacy and Terms.
10. **`CreditsPage.vue` is imported directly by the router, with no thin wrapper.** The four
    content pages have one only to supply `ContentPage.vue`'s `page` prop; this component takes no
    props. The asymmetry is deliberate.
11. **The credits page's links are white and underlined, not tint red.** `--color-tint` (#cf0000)
    on the black background is 3.65:1 — below WCAG AA's 4.5:1 for text — and this page is almost
    entirely links, so axe fails on it outright. §14.1 forbids adding a colour token without
    amending the design doc first, so an existing token was used. See Surprises: the markdown
    content pages have the same contrast problem and are not axe-tested.
12. **Source link text is the URL itself**, not a translated word "Source". Sixteen identically
    labelled links on one page give a screen reader no way to tell them apart, and a URL is data
    needing no catalogue entry.
13. **The credits page is a list of label/value rows, not a table.** It was a four-column table
    first, and that version needed a horizontal scroller at *every* width — the source-URL
    column alone is wider than a phone — so the scrollbar appeared even on wide screens with
    room to spare. Removed on the user's instruction. The list wraps instead, and
    `tests/e2e/credits.spec.ts` now asserts across five widths that neither the page nor any
    element inside it scrolls sideways, and that the page holds no `<table>` at all. The four
    `credits.column*` keys became three `credits.label*` keys; the component name is its own
    `<h2>`. The SPDX identifier is appended to the licence name only where the two differ —
    most entries would otherwise read "MIT (MIT)".
14. **US English (`license`) in the catalogue**, per AGENTS.md, against the British spelling the
    design documents and these notes use in prose.

## Surprises

- **T06 did record the upstream source URLs**, contrary to what this task's planning assumed:
  `docs/task-notes/T06.md` lines 86–110 carry the full `curl` table for all 14 components, with
  repo-move notes. All 16 URLs (the 14 plus the two wrappers) were verified to return 200 before
  being written into the manifest. aom's canonical home really is
  `https://aomedia.googlesource.com/aom/` — there is no usable GitHub mirror.
- **`oxipng/LICENSE-jsquash-wrapper` was already on disk**, so only two files were genuinely
  undocumented: `libwebp/PATENTS` and `gifsicle/LICENSE-gifsicle-wasm-browser`. Both are now
  credited and both are in §7.2's tree.
- **The licence middleware initially broke the credits page.** Mapping
  `/3rd_party_licenses/*` straight onto disk also shadowed
  `/3rd_party_licenses/components.json`, which Vite must transform into a module for
  `componentsManifest.ts` to import — the page's own script then arrived as `text/plain` and
  failed MIME checking. Fixed by serving only `<directory>/<file>`, which is what licence text
  always is.
- **`.credits-page` needed an explicit `inline-size: 100%`.** `SiteShell`'s `.site-main` is a
  column flex container and `margin-inline: auto` opts an item out of cross-axis stretching, so
  the article was sized by the table's min-content width and the whole page scrolled sideways
  instead of the table scrolling inside its wrapper. `max-inline-size` alone does not prevent
  this.
- **Firefox tears the page context down when a download starts.** The R-V2 test was restructured
  to make every assertion on the completed run before Download is pressed, with delivery as a
  tolerated final step. This is not new: the pre-existing download assertion in
  `tests/e2e/accessibility.spec.ts` fails on Firefox for the same reason.
- **`vi.stubEnv('PROD', …)` does reach `import.meta.env`** under this Vitest version; no
  `vi.stubGlobal` fallback was needed.
- **A privacy line in the compact footer costs stage height, and shortening it does not help.**
  It took the footer from one row (31px) to two (61px) below roughly 600px viewport width —
  measured at 390px and 480px, and with a 14-character line as well, because the wrap is driven
  by the number of items on the row rather than the length of any one. There was no page scroll:
  the stage absorbed the 30px, which is visible as a shorter Preview frame
  (`[data-testid="preview-frame-host"]` measured 30px shorter at 390px and identical at 1440px,
  where the footer does not wrap). The line was removed for this reason; the footer is back to a
  single row at every width, and the frame host now matches the pre-T49 measurement exactly at
  both widths. **If a future task wants a persistent line in that footer, it has to buy the row
  space first** — the item count is the constraint, not the wording.
- **The suite has pre-existing failures on this machine**, unrelated to this task and reproduced
  with every T49 change stashed: `app.spec.ts` (drawer Tab cycling), `accessibility.spec.ts`
  (Firefox download), `gallery-grid.spec.ts`, `gallery-ingest.spec.ts`, `preview.spec.ts`,
  `capability.spec.ts` and `opfs.spec.ts` on various engines. Every T49 test passes on all three
  engines.

## What the next task should know

- **The Share sentence for `content/en/privacy.md` is not committed.** That file is finished legal
  text and never mentions Share; nothing in it is falsified (§2's "we do not collect, store or
  transmit your images" stays true, because Share is an OS handoff and not a transmission to us),
  but a reader following the new footer line there finds nothing about it. A one-sentence addition
  was drafted and put to the user for approval. If it is approved, it belongs in §2.
- **Adding a dependency now means adding a `components.json` entry, or CI fails.** Committing a
  licence file into an existing component directory without listing it fails too. Both directions
  were verified by hand.
- **The `/credits` entry in `sitemap.xml` and `llms.txt` is automatic** —
  `generate-seo-files.mjs` reads `dist/*.html` — so no route list needs maintaining there.
- **`docs/technical-design.md` §12.4's last paragraph is stale**, and so is T51-A's third bullet:
  both say Privacy and Terms ship with placeholder content, but T44 shipped real legal text dated
  18 October 2026. Not corrected here, because it is not this task's text to rewrite.
- **The markdown content pages' link colour fails WCAG AA.** `--color-tint` on black is 3.65:1,
  and FAQ, Privacy, Terms and Desktop all use it for links while no axe test covers them (T47
  scoped its audits to the tool's stage roots). The credits page sidesteps it; the other four do
  not. This is R-K territory and worth a decision — either a token change in Functional Design
  §14.1 or an accepted exception recorded somewhere.
- **The credits page must stay table-free.** The regression it guards against is a horizontal
  scrollbar at widths that have room for the content; a table of component, licence, source URL
  and filenames cannot be made to fit a phone, so reintroducing one brings the scroller back at
  every size.
- **R-V2 is now load-bearing on a test, and that test is deliberately narrow in two places.** Bare
  dimension numbers are searched for in request bodies only, never URLs (Vite's hashed asset URLs
  and `?t=` timestamps contain arbitrary digit runs), and `blob:`/`data:` URLs are excluded as
  same-document handoffs. Both are explained in the spec header. "Strengthening" either one turns
  it into a flake. Its strongest assertion is that no request carries a body at all, which
  subsumes every size check. It was verified to fail against a simulated leak, not just to pass.
- **`content/en/faq.md` line 27's claim** — "No image bytes, file names, dimensions or sizes are
  sent to us or to any analytics service" — is now backed by that test rather than by assertion.
